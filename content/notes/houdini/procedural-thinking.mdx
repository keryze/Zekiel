This is a **sample note** illustrating the garden’s writing format. It does not describe a tool that has already been shipped.

## Before the first node

A procedural tool is a compact description of a family of outcomes. Its quality depends on the rules it preserves, not on how many nodes it contains.

For a roof generator, the inputs might be a footprint, a pitch, and an eave distance. The invariants might be a consistent construction order and predictable edge treatment.

## A small working vocabulary

| Concept        | Question                                    |
| -------------- | ------------------------------------------- |
| Input          | What can the artist change?                 |
| Invariant      | What must remain true?                      |
| Transformation | How does one representation become another? |
| Validation     | How do we detect an invalid result?         |

## Make intent visible

Give attributes names that describe their meaning. Keep structural generation separate from decorative detail. Build inspection points into the network.

```c
// Illustrative VEX: inspect a slope signal before combining masks.
vector up = set(0, 1, 0);
f@slope_mask = clamp(dot(normalize(@N), up), 0.0, 1.0);
```

This is a signal, not a complete snow model. Accumulation also depends on exposure, local geometry, and artistic intent.

## Test the boundaries

A useful tool handles ordinary input gracefully and communicates failure clearly. Test extreme sizes, empty selections, irregular footprints, and repeated runs with the same seed.
